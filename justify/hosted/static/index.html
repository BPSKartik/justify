        What it finds

        Four kinds of weight. Every one passes every test.

        Dead weight never breaks anything — that is why it survives. An assistant writes for the prompt in front of it, not for the codebase it cannot see, so it leaves these behind:

        Unused imports

        A module loaded that nothing calls. Every one is read, parsed and loaded on every run.

        How it works

        Seven stages. The model never deletes.

        A code graph proposes, a jury of models is asked why, a second call tries to prove it wrong, the tests decide, and a person approves. Doubt always means keep.

        1. 1IngestEvery file read once and fingerprinted; every language counted.
        2. 2Static factsSyntax trees, not text search: who uses what, across the whole repository.
        3. 3CandidatesFrameworks, dynamic lookups and re-exports are held back for judgement. Copies found in every language.
        4. 4JustifyA jury of models is asked why the unit exists, and must cite a file and line that is then checked.
        5. 5ChallengeA second call tries to prove the code is needed. If it can, the code stays.
        6. 6ProofRemoved in a temporary copy; your tests run. A file the tests never load is “not provable”.
        7. 7ReportA reason on every line, a fix plan for your AI, a ledger of every run. A person approves.

        This site stages 1–3, authorship and the score — public repositories and your own uploads, read-only.

        Your machine stages 4–6 — the jury, your tests, the proof.

        The Justify Jury · Azure AI Foundry + Claude

        Six models from four makers vote. The tests grade them.

        One model's opinion is a guess. Justify asks a jury — and then checks every juror against what the project's own tests say really happened.

        • Removing needs near-unanimity. Every juror but one must vote remove, each at 0.7 confidence or more.
        • One real reason vetoes. A keep that cites a file and line where the code is actually used stops the removal.
        • A split goes to a person. Anything the jury cannot settle is kept and flagged.
        • No keys anywhere. Foundry jurors answer to an Entra sign-in, Claude Opus 5.5 to the Claude Code sign-in — never an API key.

        What we measured

        Does it pay off? It depends on the repository.

        We ran Justify on five public repositories with AI-signed commits — 3,434 Python files, 1,013,192 lines, at each one's latest commit on 3 October — and split every finding by who wrote it.

        1. Unused code is not where AI-assisted code costs. AI-signed code carried no more of it in all five.
        2. Duplication is. Higher in three of five — 7.2× the rate of the rest in the largest repository.
        3. There is no single answer. The same assistant pays off in one repository and costs in another. Measure yours.

        Static stages and authorship, no proof. AI-signed = commits with an assistant signature, a lower bound. The first run, on 2 October, gave the same three findings.

        The jury, and proof

        The hosted audit reads code and never runs anything. To let the jury judge, and to prove each removal by running your own tests on a temporary copy, run Justify on your machine:

        pip install "justify-code[mcp] @ git+https://github.com/BPSKartik/justify"
        justify scan . --judge --prove "python -m pytest -q"

        As a local MCP server: command justify-mcp, with JUSTIFY_TEST_COMMAND (the only command it may run) and JUSTIFY_ALLOWED_ROOTS (the only folders it may read).

        Questions

        Before you trust it.

        Does Justify ever delete my code?

        No. It proposes. On your machine it removes code only in a temporary copy, runs your tests there, and writes a report. A person approves every change. The model can veto a removal; it can never force one.

        What happens to code I upload?

        It is unpacked on the server, audited, and deleted when the audit finishes. The result — names, files and line numbers, never your code — is visible only to your account, and you can delete it from your dashboard at any time. Nothing is ever sent to a model.

        How does it know which code an AI wrote?

        From signatures the assistants leave in commits: trailers like Co-Authored-By: Claude, lines like “Generated with Codex”, and the accounts agents commit as (Copilot coding agent, Devin, Jules, Cursor Agent). Code pasted from a chat window carries no signature — no tool can reliably tell it apart, and guessing would wrongly accuse people — so Justify reports it as “no AI trace”, never as human.

        What is the Justified Line Ratio?

        The share of lines that are not dead weight: lines left after removing everything with no use anywhere, divided by all lines. A team can track it per repository, per quarter, and split by authorship — the dashboard does.

        Which languages?

        Python gets the full audit: unused imports, functions, classes and dependencies, copies, the jury and proof. More than 25 other languages — JavaScript, TypeScript, Go, Java, C, C++, C#, Rust and more — are checked for copied code and counted, and every repository gets authorship.

        How is this different from a linter?

        A linter looks at one file and asks whether a name is used. Justify looks at the whole repository, asks whether the code is worth keeping, explains why with a file and line, proves removals with your tests, and splits the result by who wrote it.
